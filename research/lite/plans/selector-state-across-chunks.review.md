## Q1 Mechanism
Save -> reset -> load reproduces `choose` exactly: the only inputs are the cell's five fields, `run_id`, `schedule_seed`, the config-constant `placed_share_of_unprobed` (fault_timing.rs:82-89, set from `crash_placement_fraction`) and `WARMUP_OBSERVATIONS`. Learner assignment (`learner()`, arm_selector.rs:150-162) is a pure phase of the run id. The pooled counters (`AX_POOLED`) and the `cells` gauges are per-chunk telemetry, not learner state - correctly not carried, but the gauges must be set on import (above). No shadow state remains in the module.

## Q2 Harness semantics
Identity/cache suffix is sound; `tryAdoptRecord` (grader.ts:281-328) would otherwise adopt the big-loop record - the plan's null return is needed. Position `p = usedSeeds.length % len` is consistent with retries because `usedSeeds` grows only on accepted chunks (:940); the `slowConfirmed` path still counts a slow chunk, which then carries its state forward - acceptable. A failed candidate chunk (:868-895) still runs to `writer.shutdown()` and writes a state file; the next position must not read it - key the input on the chunk record that was accepted (store the state file's sha in the chunk record) rather than on the seed alone. Env transport: set/delete in `try/finally` around each `runOneEvaluation`, otherwise an exception in the baseline call leaks the baseline's paths into the candidate call. Panel and regression are separate commands and never see the variable. The epoch identity block (grader.ts:1125-1162) is a plain struct; adding `selectorState` is straightforward. The aos arm is `RATE_EXCLUDED` (decide.ts:29, :633), so the primary already leaves it out; "the aos arm apart" is automatic for the primary and only the per-arm read needs care.

## Q3 Statistics
Nothing to drop in code. The pooled binomial with 1.3 charged was calibrated on independent chunks (grader.ts:1273-1307 measures it on recorded declarations); on a trajectory, positions 1-3 share one leader set per cell, so a lucky or unlucky leader is counted three times and the 1.3 understates dispersion by an unknown factor. The first session's position 0 is a same-binary null read (expected 1.00) and is the built-in control; positions 1-3 are three conditioned reads. The two-seed-set replicate is honest but is n = 2: it supports a sign, not an interval. A merge decision should rest on: position 0 within the layout band; positions 1-3 each above 1.03 on both seed sets; the three long grid arms each above one (the iteration-61 pattern); aos read separately; throughput unchanged - and the plan's standing blocker should say exactly that.

## Q4 Pilot
Valid and cheaper in caveats than stated: slices are 20 s at both budgets, so quarters are the same round-robin mix (15 slices, 3 per arm). What the pilot does carry that the harness change will not: the per-arm replay corpus (campaign.rs:387, :413, grows for the session), the run cap, placement span and timer contexts. The corpus is the one that can dominate a depth read; bin the replay counters (`replay_child`, `replay_parent_admitted`) by quarter alongside depth so quarter 4 over quarter 1 can be split into selector maturity and corpus maturity. "Upper bound" is then right; without that split the pilot can mislead upward. The evaluator has no entry for a kept directory (runOneEvaluation always explores), so the plan's direct porcupine + grade calls are the right route; binning needs `runs` rows (session_offset_ms) joined to `run_depths` from the grade output.

## Q5 The window and the honest gain
The bound is right and it undercuts the filed motivation: `DISCOUNT` 0.998 caps a direction at 500 own observations, so a 0.002 reward yields about one reward per window whatever the cell's age. Carried state therefore does nothing for the base-rate wall (reviews 64, 65) unless `DISCOUNT` changes with it; the plan defers that to "after the pilot". For the rewards that exist, the state saturates inside one chunk for leaders (~3,000 of 3,600 observations) and in one to two chunks for runner-ups (~450 per chunk at coin share 0.11), so the coin share plateaus by position 1-2.
Pricing from the cache (grid arms, probe-free variant cells): learner-pick runs read depth>=8 at 0.0185-0.0192 per run, coin runs 0.0031-0.0034, so a coin run turned into a pick is worth ~0.015 events. Iteration 61 moved the share 0.147 -> 0.110 and paid +5.2% (this model says +3.4%, so it under-predicts slightly). Ramp: ~15-20k excess coin runs in the first two minutes -> +2 to +3% per chunk. Plateau: 0.11 -> 0.05 (the aos floor is 0.02 at 35k observations per learner per chunk) -> 34k runs -> +5%; 0.11 -> 0.08 -> +2.5%. Honest expectation on positions 1-3: +3 to +8%, pooled over four +2 to +6%, all in depth 8, none past depth 10. The plan's band [1.03, 1.10] is defensible; its observables ("coin share 0.03-0.05") are the optimistic end.

## Q6 Missed risks
- Calibration tables are coin-only (arm_selector.rs:461-471). A share of 0.04 cuts the control rows from ~63k to ~23k per chunk; every later proposal is read on those tables, and per-direction rows fall under what the direction reviews have called "directional only". Price this before adopting trajectory as the standard.
- Lock-in: a wrong leader self-corrects only through its own picks' credit; the runner-up's evidence arrives at ~70 observations per chunk at share 0.04, so a wrong leader lasts positions, not minutes. Read `chosen_by_direction` per position against the coin table.
- Grid arm cold start: carried state removes it on positions > 0 and leaves it at position 0; the pilot's per-arm quarter read is the diagnosis the reviews asked for anyway.
- Cold cap meeting a warm selector: the cap is a per-budget quantile of probe lengths, probes are unsteered (run_cap.rs:2-8, :17-18); chunk 2's cap converges to the same value as chunk 1's, so the mismatch lasts the cap's floor (200 completed probes per scope). The concern in the review prompt is small but nonzero on `steps per run`; the balance guard reads it.
- aos: its own cell is carried too; with ~35k observations per learner per chunk it is already at the floor, so no change is expected - which makes it the negative control the plan says it is, provided its 0.88 from iteration 61 is not re-read as a signal.
- Determinism: run ids restart at 0 per chunk, so the learner and probe phases are identical at every position; only wall-timed run counts vary, as today.

## Q7 Scope and cost
Order is right. The minimal version that answers the question is: pilot (no code), then items 1-4 plus a hand-run trajectory (four explores chained with `--set selector_state_in/out`, graded by the same porcupine + grade calls, compared by hand to the independent cache's seeds 1000-1003, which needs two more baseline chunks). Items 5-7 (identity, positions, retries, selftest, finish block, docs) are only needed for adoption and are most of the work; `expectedCost` 4 is light for them. Session cost figures (about 100 minutes per two-seed-set decision) are consistent with 300 s + ~60 s per chunk.
